Architecture

 

1. Overview

Precept is a desktop application installed on each user's PC with Microsoft ClickOnce, and updated automatically at each launch (see Installation). The calculations run on the PC. The application connects to the components shown below.

2. Licence and configuration

At start-up only, Precept reads the licence and configuration information maintained by Cleverfield. It checks that:

•the Windows user has a valid, non-expired licence;

•the user is working from the company's Windows environment, and enters the password when one is required;

•a licence is free, for concurrent licences.

The licence also tells Precept which company database to open.

3. Precept database

Each company has its own, dedicated Precept database (Microsoft SQL Server, normally hosted by Cleverfield on Microsoft Azure). It contains:

•all the forecast inputs, scenario by scenario: asset model, network constraints, decline curves, material balance data, opportunities, sequences, shutdowns, settings, economics and GHG inputs;

•all the forecast outputs (results at every node and time step, economics, emissions);

•asset-level data shared by all scenarios of an asset, such as production history uploaded to Precept, well trajectories, and the access rights of each user.

The network diagram of each scenario is kept as a file in a storage location configured for your company (cloud storage or a shared network folder). Precept copies, renames and deletes this file together with the scenario.

When a new Precept version first connects to the database, it upgrades the database structure automatically.

4. Production allocation database

Allocated production and injection history (oil, gas, water, water injection and gas injection against time, per well and per field) is used to fit decline curves, to initialise the forecast, and by the Monitoring dashboards. Two set-ups are possible:

•Direct connection (recommended): Precept reads your existing production allocation database. Cleverfield configures the connection and the queries during installation and integration.

•Upload: the allocated data are imported and stored in the Precept database.

5. Optional connections

The following are used only by the features that need them:

•Process historian (for example Aspen IP.21): high-frequency data for the Monitoring module.

•Petex GAP and Prosper, through OpenServer on the same PC (Petex GAP / Prosper coupling).

•OPM Flow, run through Windows Subsystem for Linux on the same PC, for 3D reservoir simulation (Simulation coupling).

•Precept AI, which needs internet access when it is activated (Precept AI).

6. Network ports

Precept connects to its database on TCP port 1433 (the standard SQL Server port); this port must be open from the users' PCs. Installation, updates and cloud storage use HTTPS. If a connection fails at start-up, the "Connection Checker" button appears on the ribbon to help diagnose it.

7. Connection from third-party software

Reporting tools such as Power BI or Spotfire can read the Precept database directly, using database credentials provided by Cleverfield for that purpose.
